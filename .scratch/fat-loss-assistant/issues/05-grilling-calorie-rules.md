# 05 - 热量预算与安全规则

Labels: wayfinder:grilling
Type: grilling
Status: resolved

## Question

与用户对话敲定 MVP 的热量预算算法与安全规则，产出可写进规格书的计算规格。

已固定的背景：MVP 为纯规则型（基础代谢/活动系数 → 每日热量预算），后续版本才有动态调整与 AI 教练。

需要逐项敲定（grilling + domain-modeling）：

1. 基础代谢公式选择（Mifflin-St Jeor 等）与活动系数分档，用户建档时问哪些字段。
2. 每日热量预算 = 消耗 − 缺口；缺口如何由「每周减重速率目标」推导？
3. 安全底线：最低热量下限（如不低于基代的某个比例 / 通用下限值），触及后 UI 如何提示或拦截。
4. 运动消耗是否计入（MVP 不含运动记录，则预算是否需要手动调整入口？）。
5. 平台期/体重停滞时 MVP 给什么反馈（还是留到后续版本）。

## Blocked by: 04

（热量预算的缺口推导依赖 04 号票敲定的目标模型——每周减重速率如何定义）

## Answer

**5 项决策全部落定；新增 7 个领域术语已入 [CONTEXT.md](../../../CONTEXT.md)（热量预算/BMR/TDEE/缺口/安全下限/三色状态）。**

计算规格（可写进规格书的完整链条）：

1. **BMR**：Mifflin-St Jeor（男：10×kg + 6.25×cm − 5×年龄 + 5；女：−161），档案四项（性别/出生年/身高/体重——体重取测量流最新值）。
2. **TDEE** = BMR × 活动系数：久坐 1.2 / 轻度 1.375 / 中度 1.55 / 高 1.725（标准四档，选档即用）。
3. **缺口**：日缺口 = 每周速率(kg) × 1100（换算 1 kg ≈ 7700 kcal）。
4. **热量预算** = TDEE − 缺口，随目标版本固定，不随运动/停滞自动调整。
5. **安全速率上限**：每周 ≤ 1 kg（日缺口 ≤ 1100 kcal），超标拒存目标并建议降速。
6. **安全下限**：女 1200 / 男 1500 kcal 硬底线（拒存）；预算 < BMR 但 ≥ 下限给黄色警告（可继续）。
7. **运动**：MVP 不计运动加成，无手动消耗入口（后续版本再议）。
8. **平台期反馈**：三色状态——正常（实际周均在预期 ±0.25 kg/周内）/ 偏快（快超 0.5 kg/周，提示关注）/ 停滞（连续两周不足预期 25%，建议复核记录与活动档位）；只提示不改预算，动态调整留给后续 AI 版本。

示例链（写入规格书验收用例）：女 30 岁 165cm 70kg 轻度 → BMR ≈ 1420，TDEE ≈ 1953；目标 −0.5kg/周 → 缺口 550 → 预算 ≈ 1403 → 触发黄色警告（< BMR，≥ 1200 下限）可继续；目标 −1kg/周 → 预算 ≈ 853 → 低于硬下限拒存。

后续影响：06 号票原型的今日页/目标设定页需展示预算、黄警与三色状态；07 号票规格书引用本链作验收用例。
