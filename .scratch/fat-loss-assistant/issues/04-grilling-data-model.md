# 04 - MVP 数据模型与记录流程

Labels: wayfinder:grilling
Type: grilling
Status: resolved

## Question

与用户对话敲定 MVP 的数据模型与日常记录流程，产出可直接写进规格书的领域定义。

已固定的背景：追踪粒度为全套身体数据（体重、体脂率、腰围等围度）；单位 kg/kcal（斤仅显示换算）；纯本地存储；界面中文。

需要逐项敲定（grilling + domain-modeling，同步维护 CONTEXT.md 术语表）：

1. 记录频率与提醒：每日体重必须记吗？漏记怎么处理？
2. 饮食记录粒度：按餐（早/午/晚/加餐）还是按条？每条记什么（食物、份量、热量）？
3. 「目标设定」的定义：目标体重、每周减重速率上限（安全值）、预计达成日——三者关系如何约束？
4. 体脂率/围度数据从哪来（手动输入？体脂秤导出？）。
5. 数据模型的实体清单与关系（用户档案、目标、每日记录、食物条目、身体测量）。
6. 情景压测：忘记记录、重复记录、跨天补录、目标修改后历史数据怎么办。

## Answer

**两轮 grilling 共敲定 14 项决策；领域术语已沉淀至仓库根 [CONTEXT.md](../../../CONTEXT.md)。**

记录纪律与结构：
1. 体重每日可选、不强制；漏记不产生空记录，趋势曲线连续化处理。
2. 饮食按餐分组：每日四餐槽（早/午/晚/加餐），每餐槽下多条食物条目，报表可分餐统计。
3. 热量来源：选食物 + 填份量（克），自动按每 100g 值换算，允许手动改算后热量。
4. 份量支持快捷份型按钮（「一份≈150g」一键入账），克数是存储真值。
5. 补录：任意过去日期可补/改/删，无限制。

数据模型（六实体，UI 只依赖存储抽象层 Repo）：
6. **用户档案**：性别、出生年、身高、活动系数档位（BMR 基础四项 + 体重从测量流取最新）、饮食偏好（为 AI 教练预留）。
7. **目标**：目标体重 + 每周速率（受安全上限约束），达成日自动推算并随进度动态更新；**改目标 = 封存旧版本 + 新版本生效**（GoalVersion），历史曲线可标注「当时的目标」。
8. **餐槽 → 食物条目**：条目采用**快照复制**（记录时复制食物名与营养值），食物库后续修改不影响历史。
9. **身体测量统一表**：某日某类型一个值（体重/体脂率/腰围/臀围…），加指标零改表；同日同类型允许多条，曲线用日均值。
10. **食物库**：内置精选 + 用户自定义同构存储。
11. 情景压测：同日多次体重不拦截，均值入曲线；目标达成/过期 → **维持模式**（无缺口，继续记录看趋势），再次减脂建新目标版本。

完整实体字段与关系将在 07 号票撰写规格书时展开（依赖本答案 + 01 号票存储结论）。

对其他票的影响：05 号票（热量预算）所需的 BMR 原料与速率上限定义已就位；06 号票（原型）的页面字段与流程以本答案为准。
