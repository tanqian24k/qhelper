# 06 - 网页端核心记录流程原型

Labels: wayfinder:prototype
Type: prototype
Status: resolved

## Question

用 /prototype 做一个网页端可点击原型，让用户对 MVP 的核心记录流程「长什么样、怎么用」产生具体反应。

范围（覆盖三件套闭环）：

1. 今日页：今日热量预算 vs 已摄入 vs 剩余，体重打卡入口。
2. 记一餐流程：选内置食物 → 定份量 → 入账；自定义食物兜底。
3. 记身体数据流程：体重（必）、体脂率/围度（选）的录入表单。
4. 目标设定页：目标体重 + 每周速率 → 显示预计达成日与安全提示。

原型是丢弃式的：只为验证交互与信息架构，不要求接真实数据模型，不要求美观。

## Blocked by: 04

（原型页面的字段与流程依赖 04 号票敲定的数据模型与记录流程）

## Answer

**评审结论：C「时间线·手账风」胜出，作为 MVP 界面的基线方向**；A/B 废弃，但 B 的目标管理页（历史版本封存表格）作为目标管理设计的参考输入保留在结论里。

原型经四轮用户评审迭代，沉淀出 5 条设计结论（与 04/05 号票规则共同构成规格书交互章节的依据）：

1. **记一餐 = 「本餐会话」制**：一餐常含多种食物，录入流必须是弹层内连续添加（暂存区实时小计、可单项移除），最后「完成本餐」一次入账——不是「加一条关一次弹层」。单条快速模式可作为暂存区为空时的快捷路径。
2. **记录入口必须常驻可见**：身体数据块已记时显示数值 + 修改入口，未记时显示邀请态（「今日还没打卡」+ 主按钮 + 「不强制、可补录」说明）；禁止按状态隐藏入口（首版曾把打卡按钮藏在「未记」条件里，正常状态反而找不到）。
3. **同日多次体重打卡不拦截**，曲线用日均值口径且**口径可见**——多次打卡的日期点在图上带 `*` 标记。
4. **目标编辑统一走弹窗**（三端一致的交互模式），05 号票安全规则在弹窗内实时表现：红色拦截（速率>1kg/周、预算<硬下限）、黄色警告（预算<BMR，可继续须确认）、绿色通过（显示预计达成日）。
5. **C 的信息架构**：一日一页时间线（预算块 → 身体数据块 → 各餐块 → 趋势块），悬浮 ＋ 记一餐；趋势三色状态内嵌在时间线中。

原型资产：[prototype/core-flow-prototype.html](prototype/core-flow-prototype.html)（丢弃式，含 A/B/C 三变体与本票全部修正；实现时按结论 1–5 重写，不直接复用原型代码）。
